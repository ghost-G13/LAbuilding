# 数据处理脚本说明

本文件夹包含洛杉矶建筑三维数据处理全流程的 Python 脚本，涵盖数据下载、裁剪、面积计算、高度填充、质量检查等各个环节。

---

## 脚本清单

| 脚本文件 | 主要功能 | 依赖库 |
|----------|----------|--------|
| `convert_to_geojson.py` | 将原始压缩数据转换为 GeoJSON | gzip, json, os |
| `clip_la_data.py` | 按矩形范围裁剪建筑数据 | gzip, json, os |
| `calculate_area.py` | 计算每个建筑的占地面积 | json, os, utm |
| `fill_heights.py` | 对缺失高度进行空间插值填充 | json, numpy, collections, os, time |
| `check_result.py` | 检查高度填充结果统计 | json |
| `check_confidence.py` | 检查置信度分布统计 | json, numpy |
| `quadkey_calculator.py` | 计算地理坐标的 QuadKey 索引 | math |

---

## 数据处理流程

```
原始数据（.csv.gz）
    ↓ convert_to_geojson.py
GeoJSON 格式数据
    ↓ clip_la_data.py
裁剪后的研究区域数据（la_clipped.geojson）
    ↓ calculate_area.py
增加面积字段（la_clipped_with_area.geojson）
    ↓ fill_heights.py
填充缺失高度（la_height_filled.geojson）
    ↓ 其他处理（如添加 bid 等）
最终数据（LA_building.geojson）
```

---

## 各脚本详细说明

### 1. convert_to_geojson.py

**功能**：将微软 GlobalMLBuildingFootprints 原始压缩数据（`.csv.gz` 格式）转换为标准 GeoJSON 格式。

**输入**：`part-00015-4feead82-d499-422b-94cb-c036c212127a.c000.csv.gz`

**输出**：`la_023012311.geojson`

**处理逻辑**：
- 逐行读取 gzip 压缩文件
- 每行已经是 GeoJSON Feature 格式
- 将所有 Feature 合并为标准的 `FeatureCollection` 结构
- 输出为完整的 GeoJSON 文件

**使用场景**：获取原始数据后的第一步，将非标准压缩格式转换为通用的 GeoJSON 格式，便于后续处理。

---

### 2. clip_la_data.py

**功能**：按指定的矩形经纬度范围裁剪 GeoJSON 数据，只保留完全落在范围内的建筑。

**输入**：原始 GeoJSON 数据（如 `la_023012311.geojson` 或压缩的 `.csv.gz`）

**输出**：`la_clipped.geojson`

**裁剪范围**：
- 北边界：34.081140°
- 南边界：33.990664°
- 西边界：-118.319045°
- 东边界：-118.208441°

**处理逻辑**：
- 获取每个建筑多边形的外接矩形边界
- 检查建筑的边界是否完全落在指定矩形范围内
- 保留完全包含的建筑，丢弃部分或全部超出范围的建筑

**使用场景**：从完整城市数据中提取研究区域的子集，减少数据量和后续处理时间。

---

### 3. calculate_area.py

**功能**：计算每个建筑的占地面积，并将面积字段添加到 GeoJSON 属性中。

**输入**：`la_clipped.geojson`

**输出**：`la_clipped_with_area.geojson`

**处理逻辑**：
1. 将每个建筑多边形的 WGS84 经纬度坐标通过 `utm` 库转换为 UTM 投影坐标（米为单位）
2. 使用鞋带公式（Shoelace Formula）计算多边形面积
3. 将计算结果添加到属性中：
   - `area_m2`：精确面积值（Float，单位：平方米）
   - `area_m2_rounded`：四舍五入后的面积值（Integer，单位：平方米）

**依赖库**：`utm`（需单独安装：`pip install utm`）

**使用场景**：为建筑数据增加面积属性，可用于建筑规模分析、空间统计等。

---

### 4. fill_heights.py

**功能**：识别高度缺失的建筑（`height = -1`），使用空间插值方法填充估算高度。

**输入**：`la_clipped_with_area.geojson`

**输出**：`la_height_filled.geojson`

**处理逻辑**：
1. **读取数据**：加载 GeoJSON，统计有/无高度数据的建筑数量
2. **计算中心点**：为每个建筑计算多边形中心点坐标
3. **构建空间索引**：使用网格索引（grid size ≈ 2km）加速邻近搜索
4. **查找邻近建筑**：对缺失高度的建筑，搜索同网格及相邻网格中的有效高度建筑
5. **插值填充**：取邻近建筑高度的**中位数**作为估算值
6. **标记填充**：为填充了高度的建筑添加 `height_filled: true` 标记

**关键参数**：
- `grid_size = 0.02`：约 2km 的网格大小
- 全局中位数：当建筑周围无有效高度数据时，使用全局中位数作为默认值

**使用场景**：修复原始数据中高度缺失的问题，使所有建筑都有高度值，便于三维可视化。

---

### 5. check_result.py

**功能**：检查高度填充结果，输出统计信息。

**输入**：`la_height_filled.geojson`

**输出**：控制台打印统计信息

**统计内容**：
- 总建筑数
- 高度范围（最小值 ~ 最大值）
- 平均高度
- 填充标记数（`height_filled = true` 的建筑数量）
- 使用全局中位数的建筑数
- 使用邻近插值的建筑数

**使用场景**：验证 `fill_heights.py` 的填充效果，检查填充覆盖率和数据分布。

---

### 6. check_confidence.py

**功能**：检查建筑轮廓识别置信度的分布情况。

**输入**：`la_height_filled.geojson`（或任何包含 `confidence` 字段的 GeoJSON）

**输出**：控制台打印统计信息

**统计内容**：
- 总建筑数
- 有置信度数据的建筑数量及占比
- 无置信度数据（`confidence = -1`）的建筑数量及占比
- 有置信度数据的统计：最小值、最大值、平均值、中位数

**使用场景**：评估原始数据的质量，了解建筑轮廓识别的可靠程度。

---

### 7. quadkey_calculator.py

**功能**：根据经纬度计算对应的 QuadKey 索引。

**算法来源**：Bing Maps Tile System

**输入参数**：
- `latitude`：纬度
- `longitude`：经度
- `level`：瓦片层级（1-23）

**输出**：QuadKey 字符串（如 `023012311`）

**处理逻辑**：
1. 将经纬度限制在 Web Mercator 投影有效范围内
2. 将经纬度转换为归一化坐标（0~1）
3. 计算像素坐标
4. 逐层级确定象限数字，拼接为 QuadKey

**使用场景**：
- 根据 QuadKey 下载对应区域的数据瓦片
- 空间索引和快速区域定位
- 与微软 GlobalMLBuildingFootprints 数据的分块命名对应

## 使用建议

### 按顺序执行

如果你是第一次处理数据，建议按以下顺序执行脚本：

```bash
# 1. 转换格式
python convert_to_geojson.py

# 2. 裁剪区域
python clip_la_data.py

# 3. 计算面积
python calculate_area.py

# 4. 填充高度
python fill_heights.py

# 5. 检查结果
python check_result.py

# 6. 检查置信度
python check_confidence.py
```

### 环境要求

- Python 3.7+
- 依赖库：`numpy`、`utm`（其余为标准库）

```bash
pip install numpy utm
```

---

## 注意事项

1. **路径配置**：每个脚本中的输入/输出路径需要根据实际情况修改
2. **内存要求**：处理完整城市数据时，建议至少 8GB 内存
3. **坐标系**：所有脚本使用 WGS84 (EPSG:4326) 坐标系
4. **填充精度**：`fill_heights.py` 使用邻近中位数估算，精度取决于周围建筑分布密度
